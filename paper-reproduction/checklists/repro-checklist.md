# 复现自检清单

> 每篇论文动手前过一遍 A 段，提交结果前过一遍 D 段。

## A. 动手前（30 分钟能省三天）

- [ ] 论文的**评测协议**是什么（数据集划分、指标定义、是否用 GT 位姿）？
- [ ] 官方代码的**最后一次 commit** 是否与论文版本一致？
- [ ] 仓库有没有提供**预训练权重**和**示例数据**？
- [ ] 依赖里有没有需要编译的 CUDA 算子？本机环境能否编译（算力 / 驱动 / 编译器）？
- [ ] 论文报告的数字是在什么硬件、多少步训练下得到的？
- [ ] 有没有第三方复现（Papers with Code / Issues）已经指出坑？

## B. 环境与数据

- [ ] 新建独立 conda 环境，记录 Python / PyTorch / CUDA 版本
- [ ] 固定随机种子（`torch.manual_seed` / `numpy.random.seed`）
- [ ] 数据下载后校验文件数与大小
- [ ] 预处理脚本与论文描述一致（分辨率、归一化、坐标系）
- [ ] 把关键命令写进 `repro.md`，保证能复制重跑

## C. 训练与评测

- [ ] 先跑通**最小配置**（小数据 / 少步数），确认链路无误
- [ ] 记录显存峰值与单步耗时
- [ ] 训练曲线是否正常收敛（不是 NaN、不爆炸）
- [ ] 评测脚本用的是官方提供的，还是自己重写的？
- [ ] 同一份权重跑两次评测，结果是否一致（排除随机性）

## D. 交付前

- [ ] 指标对照表：论文 vs 我的，差异写清楚
- [ ] 至少一张视觉对比图（论文截图 + 我的渲染）
- [ ] 消融或敏感性实验至少一项
- [ ] 失败与异常也记录（含报错原文）
- [ ] `paper-card.md` / `notes.md` / `repro.md` 三份齐全
- [ ] 大文件没有误提交（`git status` 检查）
